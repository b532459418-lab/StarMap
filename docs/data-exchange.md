# R15 用户资料交换

R15 让用户把同一份资料带到另一台电脑或另一个 StarMap 版本。Core 交换包由 `exchange.json` 和它引用的 `media/user/` 文件组成。导出和导入都使用相同的 Core 行语义。

## 本地使用

在 `01_Web` 下运行，使用实际私人库路径。导入前关闭目标库的个人应用。导出目录须是仓库外的新目录。

```powershell
# 从一台电脑导出，复制整个目录到另一台电脑。
npm run store:export-exchange -- --root "D:/StarMap/我的资料" --out "D:/StarMap/资料交换包"

# 先预览将新增、复用的行数和附件数，再应用。
npm run store:import-exchange -- --root "D:/StarMap/目标资料" --from "D:/StarMap/资料交换包"
npm run store:import-exchange -- --root "D:/StarMap/目标资料" --from "D:/StarMap/资料交换包" --apply
```

目标可以是空私人根，也可以是已有的当前版 SQLite 库。导入后，用目标私人根打开个人应用。进入收藏或地图查看结果。已有旧格式的根先走项目现有的库迁移。

发给好友前，使用 `--entry` 选择具体条目，或使用 `--layer` 选择该图层的全部条目。两个选项均可重复。先用 `--preview` 检查输出中的条目、依赖地点、来源和照片范围，再用 `--out` 生成复制用的包。接收者用自己的私人根预览并导入。

```powershell
npm run store:export-exchange -- --root "D:/StarMap/我的资料" --layer "starmap:interest:layer:movie" --preview
npm run store:export-exchange -- --root "D:/StarMap/我的资料" --layer "starmap:interest:layer:movie" --out "D:/StarMap/分享给好友"
```

所选图层包括其中已隐藏的条目。照片按原文件复制，可能带有拍摄地点等嵌入信息。只在确认预览范围后发送。接收方导入的实体和地点锚点初始为私有副本。

## 交换契约 v1

- `format` 为 `starmap.exchange`，`version` 为 `1`。`scope.kind` 为 `library` 或 `selection`，后者记录 `layerIds`、`entryIds`。
- `graph` 保存 Core 实体、定义、条目、来源、证据、关系、地图锚点、事件顺序和资产引用。整库包带视图偏好和已删除 ID 的记录。选择包限所选内容及引用闭包，保留所需位置锚点，省略全局视图、反向关系、旅程序列和删除记录。
- `media.files` 记录交换包内的媒体相对路径、字节数和 SHA-256。`media.registrations` 与 `media.links` 让目标端恢复附件及变体的关联。原图和已保存的预览／缩略图按引用复制。网页图片继续使用原 URL。配置、凭据、SQLite 文件、操作日志和媒体投递箱不随包迁移。
- 目标重新分配本地修订号。相同业务 ID 和内容可复用，重复导入同一包不增加记录。已删除或已编辑的同 ID、重复的业务唯一键和不匹配的附件会阻止本次导入。导入不覆盖已有记录，也不按标题或 URL 猜测不同 ID 的合并关系。
- 导入先验证类型、引用、媒体路径和字节，再提交 Core 行和附件登记。媒体文件先以独占方式复制，失败会清理本次创建的文件。交换清单上限为 128 MiB，附件按文件读取和复制。
- 交换格式的版本独立于 SQLite 和读模型。读模型出口继续提供展示快照，备份工具继续提供原库灾难恢复。

## 线上承接

| 场景 | 接入和验收 |
| --- | --- |
| 离线版迁入开通会员后的账号 | V0.7 用登录账号作为目标库，预览并应用整库包。核对收藏、关系、位置、图层顺序和已上传照片。 |
| 退订后带回本地 | V0.7 给已认证的数据所有者保留整库下载能力，下载权限与付费写入权限分开。下载后用同一格式导入本地，并断网确认可读。 |
| 多台电脑互传 | 在任一电脑导出，另一电脑导入后重开应用。原库仍可用。 |
| 把选定条目或图层给好友 | V0.8 在生成选择包或分享入口时校验发送方对每条记录和附件的权限，接收方登录、预览并确认后写入自己的库。收件账号由登录状态确定，交换包不携带账号或授权。已保存的副本与源资料各自编辑。 |

云端复用 Core 的选择与导入计划，账号授权、对象存储、会员到期后的导出入口和分享授权由服务端承接。线上验收使用两个测试账号和隔离数据，分别验证迁入、续停权限变化后带回本地，以及好友选择副本。

## 本地验收

`node --test scripts/store-exchange.test.mjs` 使用隔离 SQLite 库，覆盖探店、影视、马拉松的往返、R12 图层顺序、收藏评分和地点、原图／缩略图、幂等重导、附件损坏拒绝，以及好友副本只含所选内容、已有修改遇冲突保留。真账号和跨设备网络传输由上表对应的线上阶段验收。
