# StarMap

一个开源、本地优先的个人世界图谱与 3D 世界地图。StarMap 把地点、旅程、照片、无人机影像以及你在意的事物，放进一张属于你自己的交互式地图。

StarMap 使用 React、TypeScript、Vite 与 Cesium 构建。全新下载的仓库只包含中性的示例数据；你的旅行记录、媒体、编辑状态与环境配置默认都保存在被 Git 忽略的本地文件中。

本仓库是 **StarMap Core / 社区版**，采用 [MIT](LICENSE) 许可。它本身就是一个完整的产品，并会持续获得真正的功能更新。StarMap 最初 fork 自 [Aisland-SJL/StarMap](https://github.com/Aisland-SJL/StarMap)，现已独立开发；上游项目的署名见 [NOTICE.md](NOTICE.md)。相关版本及其许可见 [docs/editions.md](docs/editions.md)。

## 主要功能

- 可交互的 Cesium 地球，支持国家、城市、路线与镜头导航。
- Map 与 Journey 双视图及响应式玻璃界面。
- 地图图层面板：「足迹」与「想去」两个图层可以分别开关，选择会跨会话记住。
- 图层时间筛选：地图与 Journey 共用年份或日期区间，分别保存两层条件；足迹按到访区间，收藏按加入日，计划按计划到访区间。不确定日期单列，Collection 与编辑保留完整资料和草稿。
- 想去的地方：添加城市或整个国家并附上备注，可隐藏、恢复或彻底删除；与去过的城市重合时显示心形徽标。
- 本地编辑器：新增和排序国家、城市，隐藏或恢复条目，管理城市照片与无人机媒体。
- 无人机文件优先读取元数据：选择文件后立刻读取日期、GPS 坐标、绝对海拔、相对高度与相机信息。
- 只有读取不到的字段才需要用户填写；日期必填，坐标与高度均可留空。
- 横图、竖图都能完整适配的大图相册。
- 私有媒体三级管线：轻量缩略图、预览图与保留的原始文件。
- 基于 GitHub Release 的站内更新指南。
- 面向开源复用设计的隐私检查与公私数据分层。

## 快速开始

需要 Git，以及 Node.js 24 或更高版本（见 `01_Web/.nvmrc`；`package.json` 的 `engines` 也有声明）。

```powershell
git clone https://github.com/b532459418-lab/StarMap.git
cd StarMap/01_Web
npm ci
npm run dev:public
```

打开 `http://127.0.0.1:5173/`。这是纯公共预览，只读取中性示例数据，也不需要凭据。

要使用个人地图，请在源码仓库外建立私有层（正式维护工作区固定为 `StarMap/06_private/`），把 `.env.example` 复制到私有层的 `config/.env.local`，再运行 `npm run dev:personal`。独立下载的仓库可以通过 `STARMAP_PRIVATE_ROOT` 指向任意私人目录，也可使用被忽略的 `StarMap/06_private/` 兜底目录。个人配置、旅程、媒体与编辑状态在物理上都不进入源码仓库。

## 界面语言

在顶部导航旁选择中文或 English。首次访问按浏览器偏好中第一个支持的语言显示，均不支持时使用英文；手动选择保存在当前浏览器中，之后优先使用。导航、地图地点标签、鼠标操作提示，以及 Collection 文案、国家名称、搜索和名称排序同步切换；搜索仍支持其它语言的名称。缺少地点译名时回落到注册表中的可用名称。国家与城市详情、Journey 时间线和年度卡片、国家/城市编辑、地点搜索，以及想去添加/转为去过对话框也同步切换。照片与全景查看器、无人机编辑表单、图源与图层菜单、私人数据空状态与迁移提示、版本中心操作提示，以及已知本地编辑错误也跟随此设置。切换语言保留表单草稿、用户备注和标题，不会自动改写用户填写的内容；仅当注册表明确记录原名语言时显示原名副标题。发布者撰写的版本公告正文、外部诊断和未识别的错误保留原文，图源自身的地名文字不随此设置切换。

## 图源凭据——第一次使用先看这里

不配置 token 时，StarMap 仍会使用内置的低清 Natural Earth II 底图启动。需要 Cesium ion 在线全球影像时：

1. 登录或注册 [Cesium ion](https://ion.cesium.com/)。
2. 打开 [Access Tokens](https://ion.cesium.com/tokens)，创建一个应用专用的公开 token。
3. 为了最容易地在本地启动，可以保留普通公开权限；所有 Private scopes 保持关闭。正式部署时，再把 Allowed URLs 与可访问资源限制到实际需要的范围。
4. 打开私有层的 `config/.env.local`，把 token 填在 `VITE_CESIUM_ION_TOKEN=` 后面。
5. 重新启动开发服务器。

不要把 token 提交到 Git，也不要把完整 token 粘贴到 AI 对话、Issue、截图、日志或 README。浏览器端的生产 token 对访问者可见，因此应单独创建生产 token，并限制域名和资源。

如果希望 AI 带你配置，可以把下面这段话交给 Agent：

> 请先阅读 `AGENTS.md`、`README.zh.md`、`01_Web/AGENTS.md`、`01_Web/README.md` 和 `01_Web/.env.example`。先解释 StarMap 的三种图源，并询问我是需要 Cesium ion、天地图，还是只使用内置本地图源；再引导我申请所选凭据，并配置 `VITE_MAP_SOURCE`、`VITE_CESIUM_ION_TOKEN` 与 `VITE_TIANDITU_TOKEN`。不要让我把完整 token 或 Key 粘贴或展示给你；只告诉我应在外置私有层的 `config/.env.local` 中如何填写，只检查非敏感的“是否存在”和实际地图加载结果。然后运行 `npm run dev:personal` 并介绍基本操作，绝不把私人数据复制进源码仓库。

## 在 Cesium 与天地图之间切换

StarMap 的 3D 地球引擎仍然是 Cesium，图源切换只改变地球上显示的影像。需要在中国大陆访问时，可前往[天地图开发资源](https://lbs.tianditu.gov.cn/)申请自己的 Key，并把两套凭据同时写入私有层的 `config/.env.local`：

```text
VITE_MAP_SOURCE=tianditu
VITE_CESIUM_ION_TOKEN=
VITE_TIANDITU_TOKEN=
```

`VITE_MAP_SOURCE` 支持 `auto`、`cesium`、`tianditu` 或 `local`。地图底部的“图源”按钮始终列出 Cesium、天地图和本地低清兜底：常亮绿灯表示所需变量已填写（或本地图源已内置），红灯表示在线图源尚未配置且不可选择。这个判断只检查变量是否存在，不会显示或验证凭据内容。浏览器会记住上次选择的可用图源。修改 `.env.local` 后仍需重启开发服务器。两种在线凭据都会随静态网站进入浏览器，因此正式部署时要使用应用专用凭据，并在对应平台限制允许的域名和使用范围。

## 添加自己的旅程和媒体

开发模式会显示本地编辑控件，可新增和排序国家、城市，隐藏或恢复条目，选择照片封面，以及导入城市照片和无人机媒体。生产构建不会包含这些写入控件。

已知编辑和地点检索错误随界面语言显示。普通编辑返回无法识别的响应时，先刷新核对数据，再决定是否重试。照片和无人机上传先建立本地持久待办，再接收文件；刷新或重新打开浏览器后，可从「媒体待办」读取服务端记录。导入前需查看整个投递箱的影响范围，包括其他城市，并明确确认。未发送文件需重新选择并确认；结果不明的写入不会自动重传或重跑。暂不处理会保留原图，普通编辑可继续，新媒体批次和媒体删除需等待当前任务处理完成。已完成任务显示历史结果，关闭记录不会删除文件。

新增城市时，名字不决定它是哪个地点。添加足迹城市或想去的城市时，如果这个国家里已有中文名或英文名相同的地点，先不保存：表单列出这些地点的名称与大致距离，再加一项「新建独立地点」。名称一致、相距 50 km 以内的地点会默认选中，否则需要你自己选择，再用同一个按钮确认。

行程标题本身不决定这次到访属于哪个行程。把想去或旅行计划标记为去过、或添加足迹城市时，如果行程标题（你填写的，或默认的「国家 · 城市」）已被某个已有行程使用，先不保存：对话框列出这些行程的日期与城市，再加一项「新建行程」。不会替你预选，选好后用同一个按钮确认。StarMap 不会按日期把几次到访归为同一个行程。

选择无人机文件后，StarMap 会立即逐个读取可用的 EXIF/XMP 信息。文件中已经存在的值会作为“文件读取”结果锁定；只有缺失字段才可填写。缺少日期时必须补充，坐标与高度可以留空。

批量导入媒体时，参考仓库中的 `02_Assets/MediaInbox/` 模板，把真实源文件放进外置私有层的 `MediaInbox/`，然后在 `01_Web/` 运行：

```powershell
npm run media:check
npm run media:import
```

自己放进投递箱的文件夹，按文件夹名匹配到地点只是提示。第一次绑定需要你确认，只匹配到一个地点时也一样：`npm run media:check` 列出每个「文件夹 → 地点」，`npm run media:import` 在你运行 `npm run media:import -- --accept-folder-bindings` 之前什么都不写（退出码 2）。「媒体待办」的导入预览也会列出这些绑定，并单独加一个确认框。已有 `place.json` 的文件夹不受影响。编辑器上传不会占用这类文件夹：同名文件夹没有 `place.json` 时，上传会新建一个文件夹，例如 `Suzhou (1a2b3c4d)`，你放的文件夹保持原样。

导入程序不会改写 Inbox 原文件。生成文件完整写好之后才发布；`npm run media:check -- --verify` 会按内容哈希核对已经生成的原图，以及已完成媒体待办的凭据所记录的文件。个人源媒体、生成图片、本地旅行记录、编辑状态与 `.env.local` 全部留在外置私有层，不进入源码仓库。

媒体待办恢复已接到照片和无人机面板，启动与进入待办时只读发现持久记录。本地编辑与导入命令共享同库写入锁；接收完成后先展示整个投递箱的导入预览，确认后核验结果并封存完成凭据。任务查询与导入预览不写资料；已完成操作只显示历史，不恢复后来的隐藏、排序或删除。完成凭据只记录本任务的内容，不随库变大；查询任务时只比较文件大小与修改时间，不对整库计算哈希。无法完成的任务可以在确认后放弃：已收到的文件留在投递箱，已生成的输出不回滚，之后可以重新上传或导入。命令行预检只更新协调记录。备份不携带任务、锁或暂存文件，详情见[恢复范围说明](docs/local-media-recovery.md)。

库的协调记录绑定私人根的路径。私人根被移动、改名或换了盘符之后，所有写入都会报 `E_LIBRARY_ROOT_MOVED`，而不是报「库正忙」。先停掉个人预览，在 `01_Web/` 运行 `npm run library:rebind`：它打印旧 binding 与新 binding，不改任何文件。确认这就是原来的私人库后，运行 `npm run library:rebind -- --confirm` 重新绑定到当前路径。有库操作锁时命令拒绝执行。

StarMap 或媒体命令在持有库操作锁期间崩溃或被结束时，这把锁会留下来，之后的写入都会报「库正忙」。锁不会因为存在的时间长、或者进程号已经不在而被自动清除。确认持有锁的程序已经不在运行之后，在 `01_Web/` 运行 `npm run library:recover`：它打印锁的持有者、创建时间和私人根的绑定，不改任何文件。再运行 `npm run library:recover -- --confirm`：它先检查库里的数据（新库的 `quick_check` 加全量校验；还没有迁移的私人根检查 V2 文件及其地点引用），通过之后才删除锁。检查不通过时锁保留，并列出问题；请先从备份恢复，再继续写入。有新库时，不论有没有锁，它还会列出媒体的残留：没有完成的备份留下的标记（标记在时，已删除媒体的文件一直等待删除）、等待删除的媒体文件、没有资料对应的生成目录（中断的导入留下的，只列出，不删除）。确认没有备份正在运行之后加 `--confirm`，它删除这些标记，再删除等待删除的文件。没有新库的私人根，它改为列出 `data/store/` 下的残留文件，加 `--confirm` 时把它们移到 `data/store-residue/<时间>/`。

如果留下锁的同时私人根也被移动过，单用 `--confirm` 会拒绝（锁绑定的是旧路径），`npm run library:rebind` 又因为有锁而拒绝。这时改为运行 `npm run library:recover -- --confirm --rebind`：它先做同样的数据检查，通过之后把库的协调记录重新绑定到当前路径（与 `library:rebind` 相同），再删除锁。

## 想去的地方

「想去」图层标记你还没去过、但想去的地方。点击底部 dock 的「地图图层」按钮（与图源菜单是两个按钮）打开图层面板，可以分别显示或隐藏「足迹」与「想去」两个图层，浏览器会跨会话记住选择。

在个人配置（`npm run dev:personal`）中：

- **添加**：图层面板底部有「＋ 添加想去的地方」。先选国家，再在线检索城市（与新增城市相同的 Cesium ion / OpenStreetMap 检索），或手动填写城市名称与经纬度；也可以直接添加整个国家。备注可选，用来记下为什么想去。同一地点重复添加会被拒绝，并提示它已在想去列表中。
- **从城市详情添加**：点击「标记为想去」，即可直接收藏当前城市，也适合想再次到访的城市。快捷入口引用已有地点 ID，保留原名称、坐标和足迹；已有条目显示「已在想去列表」。隐藏条目同样算已收藏，可在 Collection 中恢复。先完成当前照片编辑；媒体正在处理期间暂不可添加。写入结果不明时需刷新并核对列表，再继续操作。
- **隐藏**：点击地图上的想去标记打开详情卡，选择「隐藏」。隐藏只让标记从地图上消失，条目仍然保留。
- **恢复或彻底删除**：被隐藏的条目列在图层面板「想去」开关下方的「已隐藏 N 项」里，可以逐条「恢复」或「彻底删除」。只有已隐藏的条目才能删除，删除后无法撤销。

想去的地方与去过的城市重合时，这座城市保留足迹标记并加上心形徽标；关闭足迹图层后，同一地点会显示为空心的想去标记。

顶部导航的「Collection」页列出想去图层里的全部条目，每条一张卡片，包括已隐藏的、没有坐标的，以及同时是足迹城市的地点（地图上每个地点只画一个标记，两层都有时带心形徽标）。可以按名称、国家代码或备注搜索，按「显示中 / 已隐藏」筛选，按最近加入、名称或国家排序。「在地图上查看」会切回地图、把镜头飞到该地点并打开详情卡；想去图层被关掉时会自动重新打开。在个人配置中，每张卡片还可以编辑备注、隐藏、恢复或彻底删除；来自旅行记录的 planned 条目与公开样例在这里只读，只有 planned 条目可以「标记为去过」。

去过之后，在个人配置中可以用「标记为去过」把它变成足迹：Collection 卡片的「在地图上查看」旁、地图详情卡的「隐藏」旁都有这个按钮。到访日期由你自己填写（结束日期与行程标题可选），这座城市随即进入足迹，归入这个国家代码在足迹中已有的国家；想去条目默认从列表移除，勾选「保留在想去列表（还想再去）」则保留，去过的城市会显示心形徽标。旅行计划（planned）同样可以标记为去过：这条记录本身改为已去过，日期以你填写的为准，不会新增记录。整个国家与无坐标的条目需要先具体到有坐标的城市，按钮会禁用并说明原因。已经在足迹里的城市，按钮会禁用并说明原因（本地编辑器同样会拒绝这类请求，不写任何文件），这时请改用隐藏或彻底删除。想去备注不会写进旅行记录。转换成功后页面刷新并落在新城市上；足迹图层被关掉时会自动重新打开。

想去条目保存在新库 `<private-root>/data/store/world.sqlite` 里（见下文「新库」），与其他私人数据一样位于源码仓库之外。新建的新库里想去图层为空，不会改用样例。旅行记录里 `status: planned` 的条目也会以只读方式出现在想去图层中；除「标记为去过」外，要修改请直接改旅行记录。

公开构建与 `dev:public` 显示中性的三条样例（努克、特罗姆瑟、阿克雷里；阿克雷里与示例旅程重合，用来演示心形徽标），不包含任何添加、隐藏、删除或「标记为去过」入口。强制样例模式（`VITE_TRAVEL_ATLAS_DATA_MODE=sample`，或开发时的 `?data=sample`）用来预览公开版：同样只显示这份样例，即使在个人配置中本地编辑器也整个关闭，不渲染任何编辑控件。

## 已有旧格式数据的用户如何迁移

个人配置读新库（见下文），没有迁移之前读早期版本 `<private-root>/data/v2/` 里的 V2 文件；全新的私人目录从空地图开始。在 V2 格式之前建立的私人目录，数据是旧格式，StarMap 不再读取。迁移之前，地图上显示迁移提示，本地编辑器拒绝保存，媒体导入也拒绝运行，所以不会在没迁移的数据旁边写出任何东西。StarMap 不会自行迁移、移动或改写你的文件。

当前版本已不再带迁移工具；提交 `4fd32a9` 是最后一个带迁移工具的版本。先在那里迁移，再回到最新版本：

```powershell
git checkout 4fd32a9
cd 01_Web
npm ci
npm run identity:check                  # dry-run：看报告，不迁移
npm run identity:check -- --apply       # 写出 V2 文件
git checkout main
npm ci                                  # 回到最新版本，然后刷新页面
```

应用之前，先处理 dry-run 报告里需要你决定的项目。迁移之后，旧文件以及早期版本写下的 `data/data-mode.local.json` 标记都是 StarMap 不再理会的残留，删留随意。完全不需要旧数据的话，也可以直接把四个旧文件从 `data/` 移走。完整步骤、决定文件的写法，以及迁移对媒体的影响，见 [01_Web/README.md](01_Web/README.md#migrate-legacy-format-data)（Private Data Format 一节）。回到最新版本之后，私人目录里是 V2 文件、只能查看：再按下文迁移到新库。

## 新库

个人配置把资料库放在一个 SQLite 文件 `<private-root>/data/store/world.sqlite`（新库）里。这是这一版写入个人数据的唯一方式；早期版本 `data/v2/` 里的五个 V2 文件只读，作为迁移的输入。私人根里有什么，决定个人预览怎么做：

- **有新库**（`data/store/world.sqlite` 存在）：App 读写新库。
- **有 V2 文件、没有新库**（早期版本的私人目录，或者用 `npm run backup -- restore` 恢复出来的目录）：数据只读显示，并有提示「个人数据还没有迁移到新库，现在只能查看，编辑不会保存。」所有保存、上传、导入和媒体待办都返回 `E_STORE_MIGRATION_REQUIRED`，什么都不写；`npm run media:import` 以退出码 2 拒绝，`npm run media:check` 照常预检。请按下文迁移。
- **什么数据都没有**：个人预览启动时建立一个空的新库。构建、公开配置和命令行都不会建库。
- **`data/store/` 下有残留文件、没有新库**（中断的迁移或恢复留下的）：同样只读，返回 `E_STORE_RECOVERY_REQUIRED`；不会在残留上建库。`npm run library:recover` 列出这些文件；确认没有迁移或恢复正在运行之后，`npm run library:recover -- --confirm` 把它们移到 `data/store-residue/<时间>/`（只移动，不删除）。
- **还没有迁移到 V2 的旧格式文件**：同上文（先在提交 `4fd32a9` 上迁移）；`store:migrate` 会拒绝。

在 `01_Web/` 迁移有 V2 文件的私人根：

```powershell
npm run backup -- create --root <私人根> --out <新的备份目录>   # 先备份 V2 文件与媒体
npm run store:migrate                 # 预演：各类数量、原样保存的 V2 键、unresolved 列表元素、比对结果；不写任何文件
npm run store:migrate -- --apply      # 创建 data/store/world.sqlite；V2 文件保持原样
```

预演在内存里建库，把 App 将要读到的结果与 V2 文件比对。有没有完成的媒体待办时 `--apply` 会拒绝（先在恢复中心完成或放弃它）；它在库锁之下建库，登记已经导入的媒体，重新打开后用同样的方法检查，有任何不一致就把新库删掉。个人预览可以开着：它发现新文件之后自动刷新页面，之后的保存写入新库。V2 文件和备份请保留，作为迁移之前的副本。

新库保存全部编辑：添加足迹城市与国家、彻底删除已隐藏的国家，想去条目的添加、备注、隐藏与彻底删除，标记为去过（包括同名行程的选择），国家、城市、照片的排序与隐藏和封面，以及媒体（上传、导入、恢复中心的媒体待办、彻底删除已隐藏的媒体）。编辑规则与早期版本相同，但保存之后不再刷新页面：修改就地生效，镜头、时间筛选、当前选择、填了一半的表单，以及其他页面的滚动位置都保持不变。在另一个标签页保存的修改、命令行（`npm run media:import`）写入的内容，会自动出现在已经打开的页面上。保存进行时地球暂停渲染（最多 1.5 秒），之后画出结果。正在编辑的记录在别处被改过时，编辑区列出旧值和新值，保存要等你选择「保留我的修改」（只用你改的字段覆盖新数据）或「采用新的内容」；记录在别处已被删除时只能放弃，备注可以先复制。与另一个标签页的保存撞上时，只要自己的记录没被改过，就基于新数据自动重发。结果无法确认的保存会用同一个请求重试：先立即重试一次，开发服务器重新应答后再试一次，仍然无法确认就锁住整个页面直到刷新，绝不重复写入。新库打不开时（另一个进程正在写入、库的格式这个版本不认识、文件完全读不出），页面显示错误，绝不回落到 V2 文件。

新库里的媒体有两条与早期版本不同的规则：

- **投递箱只是媒体进来的地方，不是保存的地方。** 文件导入之后，它的资料就在新库里：在应用里修改资料不会改动投递箱，之后投递箱里的变化也不会改写资料。文件在投递箱里移动或改名（内容不变）仍是同一条资料，整个文件夹改名也一样；文件从投递箱移走，资料保留，只把来源记为缺失。文件夹绑定和 sidecar（`media.json`）只在文件第一次导入时生效；移到另一个城市文件夹的资料，地点不变。想让改过的 sidecar 或文件夹对已经导入的资料生效：先运行 `npm run media:check -- --reread <投递箱里的路径>` 看差异，再运行 `npm run media:import -- --reread <投递箱里的路径>` 写入。
- **同一内容的两个来源是两条资料。** 各有自己的标题、排序和封面，共用一份生成文件。上传照片（或者媒体待办里的文件）总是得到一条新资料，之前彻底删除过的照片也一样；手动放进投递箱的文件，用 `npm run media:import -- --reimport <投递箱里的路径>` 达到同样的效果。

有些投递箱的变化要先确认，导入才会写入：彻底删除过的照片又出现了，同一路径的文件换了内容（它成为一条新资料，旧的保留），或者同一内容对应多条资料。恢复中心在导入旁边列出这些匹配，并给出一个勾选项；命令行加 `--accept-source-matches`（按名称匹配的文件夹仍用 `--accept-folder-bindings`）。`npm run media:check` 只读新库，预览开着时也可以运行；`npm run media:import` 在库锁之下写入。一次导入 200 张左右时，预览在保存它们的那一刻会停顿约 0.15 秒，这期间恢复中心显示「处理中」。

早期版本创建的新库，打开时可能报 `E_STORE_UPGRADE_REQUIRED`。停掉预览，在 `01_Web/` 运行一次 `npm run store:upgrade`。在加入媒体之前创建的新库，升级会加上媒体登记，并登记已经导入的媒体，之后的导入不会多出 V2 不会新增的内容。在这一版之前创建的新库，升级会给每个没有填访问日期、手动添加的国家补上访问条目：StarMap 现在按这个条目识别手动添加的国家，你的国家、地区和顺序都不变。旧格式的备份在恢复时自动升级。

非正常停止之后的检查发现损坏、但数据还能读出时，新库以只读方式打开：页面照常显示数据，并持续显示提示「新库可能已损坏，当前只读。请从备份恢复：npm run store:restore」；所有保存都被拒绝（`E_STORE_READ_ONLY`），什么都不写。预览运行中发现损坏也一样。请从备份恢复（见下文），再把 `STARMAP_PRIVATE_ROOT` 指向恢复出来的私人根；`npm run library:recover` 会列出检查发现的问题。

这一版不再写 V2 文件。需要 V2 格式的数据时（存档，或者给早期版本的 StarMap 用，例如提交 `e85f647`），运行 `npm run store:export-v2 -- --out <新目录>`：它把新库导出成五个 V2 文件和媒体来源索引，列出 V2 表达不了的内容，并列出早期版本的 `npm run media:import` 之后会新增、改变、移除哪些媒体（同一内容的多条资料会合并成一条，文件已经不在投递箱里的资料会消失）。还有已删除的媒体文件在等待删除时，导出会拒绝。新库和它的备份请保留：导出从不删除任何东西。把 `data/store/` 移出私人根之后，这个私人根又回到只读、等待迁移的状态。

新库的备份与恢复包含媒体（`MediaInbox/` 与 `media/user/`；不包含 `config/`、`data/v2/`（含 V2 的媒体来源索引）与 `operations/`：新库有自己的媒体登记，恢复时逐个核对登记的生成文件）：

```powershell
npm run store:backup -- --out <新目录>
npm run store:restore -- --from <备份目录> --to <新私人根>
```

把新库的读模型（`starmap.read-model`：App 读取的全部地点、记录、条目与视图设置，不含媒体登记、回执等只有库自己保存的表）导出成一个 JSON 文件：

```powershell
npm run store:export-read-model -- --out <新文件>            # 全部
npm run store:export-read-model -- --out <新文件> --public   # 只导出标为公开的内容及其依赖
```

输出位置的规则同其他导出（在私人根之内或本仓库之外，从不覆盖已有文件），写出之前先通过完整校验。公开导出包含地图的显示设置，所以地图默认镜头的坐标会公开；媒体发布时不带原始文件名。

有没有完成的媒体任务时，备份会拒绝。备份先在库锁之下（几秒钟）做完整性检查、生成数据库的一致快照；然后释放库锁，预览可以照常保存，再按 `npm run backup` 的规则复制媒体：媒体目录里有白名单之外的文件就拒绝备份，每个复制出的文件都要与原文件的 SHA-256 一致。清单记录每个文件的大小和 SHA-256，最后写完成标记。恢复先核对清单，再新建一个私人根，放入新库和媒体，逐个核对媒体文件的 SHA-256（任何一个不一致，恢复失败，新私人根删除），再运行 `integrity_check` 与全量校验，永远不覆盖任何东西。`config/` 请自己复制，再把 `STARMAP_PRIVATE_ROOT` 指向新私人根。一万张照片的备份要几分钟，主要花在文件的个数上。私人根有新库时，下文的 `npm run backup -- create` 会改用同一个实现，并在输出里说明。所有输出目录都必须在私人根之内或者在本仓库之外，并且不能在私人根的媒体目录或 `data/` 之内。详见 [整库备份与恢复说明](docs/local-backup.md)。

一个私人根只运行一个个人预览：开发服务器会一直打开新库。`npm run build:personal` 以只读方式读新库，预览开着时也可以构建。构建的数据在单独的文件 `data/read-model.<hash>.json` 里，页面启动时加载：部署整个构建目录，并通过网页服务器打开，不要直接打开 `index.html` 文件。正在使用的库不要放在 OneDrive 这类同步目录里，只同步已经完成的备份。预览是被强行结束、而不是正常停止的，下次启动会先运行 SQLite 的 `quick_check`。

预览会自己清理新库的记录：打开新库时，以及每保存 200 次之后，删掉过期的保存回执（30 天之内的、或最近 1 万条之内的都保留）和过期的诊断记录（保留一年之内的最近 5 万条）。清理分小步进行，在保存返回之后才做，腾出的空间还给文件系统。

## 构建与检查

整库备份的首版工具已支持 V2 数据、媒体来源索引、原图与网页媒体的离线目录存档。先停止自己的预览和导入任务，在 `01_Web/` 运行 `npm run backup -- create --root <明确的私人目录> --out <新备份目录>`；有新库的私人根会改用 `store:backup` 的实现（见上文）；恢复出来的 V2 私人根要先迁移才能编辑。恢复命令默认只预览，添加 `--apply` 后恢复到全新目录，原库保留供回退，启用由用户手动完成。配置凭据不进入备份，已有目录始终拒绝覆盖。范围、命令和边界见 [整库备份与恢复说明](docs/local-backup.md)。

在 `01_Web/` 中运行：

```powershell
npm run lint
npm test
npm run build:public
npm run privacy:check
npm run media:check
```

`npm test` 运行全部单元测试与脚本测试（`src/**/*.test.ts` 与 `scripts/**/*.test.mjs`，纯 `node --test`，需要几分钟）。`npm run build:public` 会在 `01_Web/dist/` 生成不带本地编辑器的静态公开站点：任何构建都不含编辑器的客户端代码，公开构建里一旦出现，CI 就会拒绝。`npm run release:check` 还会要求工作区干净，只把 Git 已跟踪文件归档到系统临时目录，在这个“无私有层”的洁净环境里重新安装依赖，并运行 Lint、测试和公开构建。这些命令只继承净化过的环境变量（搜索路径、主目录与临时目录、区域设置、代理设置），不带上 `STARMAP_PRIVATE_ROOT`、`VITE_*` 和各类 token；某一步失败时会打印它已经输出的内容。这样从机制上证明私人内容无法混入公开发布。`build:personal` 只用于你自己控制的私人部署。隐藏的内容不会进入个人构建：被隐藏的国家、城市、想去条目、照片和航拍，连同只能经由它们到达的内容，都不进入构建的数据，也只复制显示得到的媒体文件。开发服务器仍有全部数据，因为编辑器要靠隐藏的条目做「恢复」和「彻底删除」。

### 公开构建的缓存

构建方式沿用 [Cesium 官方的 Vite 示例](https://github.com/CesiumGS/cesium-vite-example)：Cesium 的代码打进一个带内容哈希的文件，Cesium 运行时要加载的文件原样复制到以所装 Cesium 版本命名的目录。托管时可以这样缓存 `dist/`：

| 路径 | 地址何时变化 | 建议的 `Cache-Control` |
| --- | --- | --- |
| `index.html` | —（它指向当前的各个文件） | `no-cache` |
| `assets/*`，包括 `assets/cesium-<hash>.js` | 内容变了（哈希在文件名里） | `public, max-age=31536000, immutable` |
| `cesium/<版本>/*`（Cesium 的 `Workers`、`Assets`、`Widgets`、`ThirdParty`） | 升级 Cesium 时（新版本用新目录） | `public, max-age=31536000, immutable` |

Cesium 单独成一个文件，所以只要应用的改动没有用到新的 Cesium 接口，这个文件的名字不变，已缓存的副本可以继续使用。

研发时可在 `01_Web/` 运行 `npx playwright install chromium`、`npm run test:browser`，自动检查语言草稿、城市选择、想去快捷入口、媒体重试、转足迹和手机面板。测试使用新建的临时合成数据目录，不访问真实私人数据；端口 5173 已占用时会拒绝启动。检查分为关键流程、媒体恢复和时间筛选三组，可以用 `--critical-flows`、`--media-recovery`、`--time-filters` 单独运行，再加 `--shard=<序号>/<总数>` 重跑 CI 的某一片；`npm run build:public` 之后，`npm run test:browser -- --public-smoke` 检查公开构建本身。`npm run perf:browser` 单独测量 1,000 条合成条目的界面与滚动表现，数据只作为本地研发基线，不作为发布验收或 CI 性能阈值。配置与报告位置见 `01_Web/README.md`。
